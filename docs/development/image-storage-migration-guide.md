# 画像保存先変更 操作手順書

## 1. 概要

SETTING画面から、アプリが管理する画像保存先を別のローカルディレクトリへ変更できる。

変更時は画像を新しい場所へコピーし、全ファイルのSHA-256が一致した場合だけ設定を切り替える。旧保存先は自動削除しない。

## 2. 変更前の準備

1. [バックアップ・リストア手順](./backup-restore-guide.md)に従ってバックアップを取得する。
2. 新しい保存先のドライブに十分な空き容量があることを確認する。
3. 画像アップロードや完全削除を行っている画面がないことを確認する。
4. ネットワークドライブを使用する場合、FastAPIを実行するユーザーに読み書き権限があることを確認する。

## 3. 保存先を検証する

1. 左メニューから`SETTING`を開く。
2. 「画像保存先」の「新しい画像保存先」へパスを入力する。
3. 「保存先を検証」を押す。
4. コピー対象のファイル数、データ量、移行先の空き容量を確認する。
5. エラーが表示された場合は、内容を修正して再検証する。

Windowsの例:

```text
D:\PegmatiteImages
```

移行先に既存の`images`ディレクトリがある場合、そのディレクトリは空でなければならない。既存画像への上書きや混在は行わない。

## 4. コピーと切り替え

1. 検証結果が正常であることを確認する。
2. 「コピー・照合して切り替える」を押す。
3. 確認ダイアログの内容を読み、実行する。
4. 完了メッセージが表示されるまで画面を閉じない。
5. 表示中の画像保存先が新しいパスへ変わったことを確認する。

処理中は画像のアップロードと完全削除が排他制御される。

## 5. 変更後の確認

1. `VAULT`でサムネイルを確認する。
2. 複数の標本詳細で表示用画像を確認する。
3. 新しい画像を1件追加し、新しい保存先へ作成されることを確認する。
4. アーカイブ画像のプレビューを確認する。
5. FastAPIを再起動し、保存先が維持されることを確認する。

保存先は`RUNTIME_SETTINGS_FILE`で指定されたJSONへ絶対パスとして保存され、`.env`の`IMAGE_STORAGE_ROOT`より優先される。

## 6. 旧保存先

- 旧保存先は自動削除されない。
- 新しい保存先で十分に動作確認するまで保持する。
- 削除する場合は、バックアップと新保存先の整合性を確認してから利用者が明示的に行う。
- アプリは切り替え後、旧保存先を更新しない。

## 7. エラー時

- コピーまたはSHA-256照合に失敗した場合、設定は切り替わらない。
- 移行用の一時ディレクトリは失敗時に削除される。
- 旧保存先は変更されない。
- 移行先の`images`が空でない場合は、別の空ディレクトリを指定する。
- 権限エラーの場合は、FastAPI実行ユーザーのフォルダ権限を確認する。
