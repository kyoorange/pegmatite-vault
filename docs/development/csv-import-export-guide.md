# CSV入出力 操作手順書

## 1. 対象

Pegmatite VaultのSETTING画面から、登録データをCSV形式で出力・取り込みする手順を説明する。

CSV入出力の対象は次のデータである。

- 標本
- 標本と鉱物の関連
- 鉱物種
- 鉱物分類
- 採集地
- 入手経路
- 画像メタデータ（出力のみ）

## 2. 重要事項

- CSV出力ZIPには画像ファイル本体を含まない。
- CSVインポートでも画像メタデータは取り込まない。
- 画像を含めて環境を復元する場合は、PostgreSQLと画像保存先を一組にしたバックアップを使用する。
- インポートは既存データを削除しない。
- 同じIDのデータは更新され、存在しないIDのデータは追加される。
- 確定後に元へ戻す機能はない。重要なデータへ取り込む前にバックアップを取得する。

## 3. 事前準備

1. PostgreSQL、FastAPI、フロントエンドを起動する。
2. 画面下部のシステム状態が正常であることを確認する。
3. ブラウザで`SETTING`を開く。
4. 「データベース」が「接続済み」であることを確認する。
5. 重要な環境では、DBと画像保存先を事前にバックアップする。

## 4. CSVを出力する

1. 左メニューから`SETTING`を開く。
2. 「データ管理」までスクロールする。
3. 「CSV出力」を押す。
4. ZIPファイルのダウンロードが完了するまで待つ。
5. ダウンロードしたZIPファイルを安全な場所へ保存する。

ファイル名は次の形式になる。

```text
pegmatite-vault-export-YYYYMMDDTHHMMSSZ.zip
```

日時部分はUTCである。

### 4.1 ZIPの内容

| ファイル | 内容 |
| --- | --- |
| `mineral_classes.csv` | 鉱物分類 |
| `minerals.csv` | 鉱物種 |
| `localities.csv` | 採集地 |
| `acquisition_methods.csv` | 入手経路 |
| `specimens.csv` | 標本 |
| `specimen_minerals.csv` | 標本と鉱物の関連 |
| `images.csv` | 画像メタデータ |

各CSVはUTF-8 BOM付きで、IDと外部キーを含む。

## 5. CSVをインポートする

### 5.1 ZIPを選択する

1. 左メニューから`SETTING`を開く。
2. 「データ管理」の「CSV取込」を押す。
3. Pegmatite Vaultから出力したZIPファイルを選択する。
4. 事前検証が完了するまで待つ。

ZIPを展開して個別のCSVを選択するのではなく、ZIPのまま選択する。

### 5.2 検証結果を確認する

検証が成功すると、次の予定件数が表示される。

| 表示 | 意味 |
| --- | --- |
| 追加 | DBに同じIDがなく、新しく登録されるデータ |
| 更新 | DBに同じIDがあり、CSVの内容で更新されるデータ |
| スキップ | インポート対象外のデータ。現在は画像メタデータ |

次の点を確認する。

1. 追加・更新件数が想定内である。
2. 意図せず大量の更新が発生しない。
3. 「インポート可能です」と表示されている。
4. 使用しているZIPが目的の環境・世代のものである。

### 5.3 インポートを確定する

1. 検証結果の「この内容で確定」を押す。
2. 確認ダイアログで、同じIDのデータが更新されることを確認する。
3. 問題がなければ確定する。
4. 「インポート完了」が表示されるまで画面を閉じない。
5. 完了後、追加・更新・スキップ件数を確認する。

確定処理は全テーブルを1つのトランザクションで更新する。途中で失敗した場合、変更は全体がロールバックされる。

## 6. 検証エラーへの対応

検証に失敗すると、ファイル名、行番号、項目名、問題の内容が表示される。

| エラー | 主な原因 | 対応 |
| --- | --- | --- |
| 必要なCSVがありません | ZIP内のファイル不足 | Pegmatite Vaultから出力した元のZIPを使用する |
| CSVヘッダーが一致しません | 列名・列順の変更 | ヘッダーを出力時の状態へ戻す |
| UUID形式が不正です | IDの編集ミス | 表示された行のIDを修正する |
| 整数形式が不正です | 番号・整数IDの編集ミス | 数値以外の文字を除く |
| IDが重複しています | 同じCSV内に同一IDが複数存在 | 重複行を確認して1行にする |
| 関連データが存在しません | 外部キーの参照先がない | 参照先CSVまたはDBに対象データを用意する |
| 展開後のサイズが上限を超えています | ZIPが大きすぎる | 対象ファイルと内容を確認する |

修正後は「CSV取込」からZIPを選び直し、再度検証する。

## 7. 検証トークン

- 検証成功後の確定操作は30分以内に行う。
- 30分を過ぎた場合はZIPを選び直して再検証する。
- 一度確定に使用した検証結果は再利用できない。
- 検証後にDBの状態が変わり整合しなくなった場合、再検証を求められることがある。

## 8. 画像の扱い

`images.csv`には画像名、状態、ファイルサイズなどのメタデータが含まれるが、画像ファイル本体は含まれない。

壊れた画像参照を作らないため、CSVインポートでは`images.csv`の行をスキップする。画像を移行する場合は次の両方を同じ時点の組として扱う。

1. PostgreSQLのバックアップ
2. `IMAGE_STORAGE_ROOT`で指定した画像保存先

## 9. インポート後の確認

1. `HOME`を開き、最近追加した標本を確認する。
2. `VAULT`で標本件数と代表的な標本を確認する。
3. `LIBRARY`で鉱物分類と鉱物を確認する。
4. `ADMIN`で各マスタの件数を確認する。
5. 標本詳細を開き、鉱物、採集地、入手経路の関連を確認する。
6. `SETTING`へ戻り、DBと画像ストレージの状態を確認する。

## 10. 問題が発生した場合

- 検証中のエラーではDBは変更されない。
- 確定処理がエラー終了した場合、DB変更はロールバックされる。
- 確定成功後に内容が期待と異なる場合は、追加編集を続けず、事前に取得したバックアップからの復元を検討する。
- 画像が表示されない場合はCSVではなく、画像保存先とDBバックアップの世代が一致しているか確認する。
